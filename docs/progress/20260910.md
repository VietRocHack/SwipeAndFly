## 2026-09-10 - Remove Docker, split backend/frontend deploy

Executed the backlog item from the previous session (deferred then to
save session usage): dropped the single-container Docker architecture
entirely in favor of the migration guide's default topology. See ADR
0004 for the full decision record.

- Confirmed with Vuong that `swipeandfly.world` (the old VM deploy) is
  dead, which unblocked removing everything nginx-related.
- Removed: `Dockerfile`, `cloudbuild.yaml`, `docker-compose.yml`,
  `docker-compose.prod.yml`, `user_conf.d/`, `.dockerignore`,
  `scripts/deploy-prod.sh`, the placeholder top-level `public/` dir, and
  `backend/src/routes/frontend_routes.py` (Flask's static-file-serving
  catch-all, now redundant since Firebase Hosting serves the frontend
  directly).
- Backend now deploys as its own Cloud Run service straight from source
  (`gcloud run deploy --source=backend`, Google Cloud Buildpacks) -
  added `backend/Procfile` and `backend/.python-version` to control the
  start command and pin the Python version buildpacks previously got
  from the Dockerfile's base image.
- Frontend now builds to `frontend/dist` and is served directly by
  Firebase Hosting; `firebase.json` rewrites only `/api/**` and
  `/video_analysis/**` to the backend instead of rewriting everything.
- Rewrote `scripts/deploy.sh` and `.github/workflows/deploy.yml`: build
  frontend, `gcloud run deploy --source` the backend, `firebase deploy`
  hosting - no more Cloud Build/Docker step, no more `VITE_MAPS_API_KEY`
  build-arg workaround (it's just an env var for `npm run build` now).
- Local dev is now two plain processes (`python backend/main.py` +
  `npm run dev`, Vite proxying `/api` + `/video_analysis` to Flask) -
  updated `frontend/vite.config.ts`'s proxy, `README.md`, and
  `CLAUDE.md` accordingly. Also dropped `.env.sample`'s
  `GCLOUD_ADC_PATH` (was only for the Docker volume mount) and fixed
  `README.md`'s stale AWS-credentials instructions while rewriting that
  section.
- Marked ADR 0001 superseded by new ADR 0004; updated `docs/backlog.md`
  and `docs/runbook.md` to match.

## Known risk - not yet verified

Video analysis imports `cv2`, which needs `libgl1`/`libglib2.0-0` to
import at all (a real bug hit and fixed in the original Dockerfile, see
the 2026-09-09 entry below). Google Cloud Buildpacks has no supported way
to install arbitrary apt packages the way the Dockerfile's `RUN apt-get
install` did. This was flagged to Vuong before proceeding; he chose to
go full-Buildpacks anyway rather than keep a backend-only Dockerfile.
**Next deploy needs to confirm `/video_analysis/analyze_videos` still
works** - if it 500s with a `libGL.so.1` import error, the fallback
(reintroduce a small backend-only Dockerfile) is documented in ADR 0004
and `docs/backlog.md`.
